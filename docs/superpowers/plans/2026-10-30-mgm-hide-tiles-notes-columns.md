# Extending card hide/show to tiles, notes, and table columns

> Extends `docs/superpowers/plans/2026-10-29-mgm-card-hide-show.md` (shipped
> in #63). Same `mgm_ui_prefs` table, same `hiddenSections` map, same
> sanitizer, same RLS, same `MGM.hideSection`/`restoreSection`, same restore
> panel. No schema change, no new table, no new sanitizer.

## Final counts, mechanically verified against the live markup

| type | count | verified by |
|---|--:|---|
| cards (existing, #63) | 60 | unchanged |
| stat tiles | 33 | id/runtime bijection, 0 duplicates |
| freestanding intro notes | 12 | 1 per tab except Report |
| table columns | 106 | id/runtime bijection, 0 duplicates |
| **total** | **211** | `HIDDEN_SECTION_IDS.length === HIDDEN_SECTION_LABELS.length === 211` |

The owner's brief asked for a count check at every stage, named because card
and tile counts were both wrong on first guess earlier in this build (45 vs
60). Three corrections happened here too, caught before shipping rather than
after:

1. **A conditionally-rendered table was missed on the first DOM sweep.**
   `staffing-crm-not-on-roster`'s table only renders when the pipeline has
   leads from CRM owners not on the roster — in the state used for the
   investigation, it never appeared. Caught by cross-checking the DOM-derived
   table count against an exhaustive source-level count of every `<table>`
   occurrence (48, not 46 — two more used a `style=` attribute and were
   missed by a bare `<table>` grep too).
2. **`additions-source-mix`'s per-year columns have no stable identity.**
   `HORIZON_YEARS` is admin-editable (1–10), so the column *set* is
   runtime-variable, unlike `progs`/`STREAM_KEYS`/`MONTH_NAMES`, which are
   hardcoded engine constants with stable keys. Excluded, same reasoning as
   the owner's row-identity-column exclusion.
3. **`additions-scenario-compare` has no stable columns beyond "Measure"
   at all.** The "Current (live)" column was assumed static; reading
   `MGM.renderCompare`'s source showed it is generated by the same
   `runs.map()` as every scenario column — not a fixed second column, just
   the first entry of the same unbounded, user-named, user-reorderable list.
   The whole table contributes zero hideable columns.

## Scope decisions (owner-approved)

- **Notes: 12, not 15.** The stable per-tab intro line only. The three
  conditional status/warning banners (pipeline's 4-state "not signed in /
  loading / error / ok" banner, cost's "costs unset", staffing's "capacity
  unset") are excluded — same reasoning as the two excluded error cards: a
  hide must never be able to suppress a live data-quality warning.
- **Columns exclude Report's 5 tables entirely.** `MGM.renderers.report` is
  an independent renderer, not a shared DOM node with the live tabs — a
  column hidden on Cashflow would not automatically hide in the Report's own
  (already different: 8 columns there, 9 on the live tab) copy of that
  table. A column silently missing from a generated/printed/emailed
  deliverable is a worse failure than a missing card.
- **Columns exclude 2 control columns**: the blank-header "▸ months" expand
  toggle on `additions-roll-forward`, and the blank-header row
  reorder/delete tools on `historical-signups-losses`. Interactive controls
  wearing a column costume, not data.
- **Columns exclude the leftmost row-identity column of every table**
  (Year, Group, Stage, Owner, Rep, Region, Stream, …). Owner's addition,
  mid-investigation: hiding it doesn't declutter, it makes every other
  column in that row unreadable. Excluded by category, not left as a choice.

## Containment — unchanged from #63

`hiddenSections` still never enters `MGM.state`. Every id minted here —
tile, note, or column — lives in the exact same `MGM.uiPrefs.hiddenSections`
map as the original 60 card ids, written only through
`MGM.applyHiddenDelta`, read only from `mgm_ui_prefs`. Nothing new touches
`mergeState`, `cloudSave`, or `exportJSON`.

## Where each new type carries its id

- **Tiles**: `data-card` on the `.sign` div, via an explicit `id` parameter
  threaded through the `sign(k, v, d, cls, id)` helper — never derived from
  `k`, the same reasoning as the About tab's `card()` helper: the label is
  stable today but deriving from it would silently orphan a hide the moment
  someone edits it.
- **Notes**: `data-card` directly on each tab's `<p class="sub">` line.
- **Columns**: `data-col` on the `<th>`. This is a genuinely different
  attribute and a genuinely different DOM mechanism from the other three —
  see below.

## Why columns need a different mechanism, not just a different attribute

Cards, tiles, and notes are each ONE element; `display:none` on that node is
the whole mechanism, and `decorateHiddenSections()` (unchanged from #63)
already handles all three for free, since all three carry `data-card`.

A table row is generated by `.map(r => ...).join('')` at render time with no
per-cell id — there is nothing to tag the way a card is tagged. The `<th>`
carries `data-col`; every other cell in that column is found by its
**position**, not an id of its own. `MGM.decorateHiddenColumns()` is a new
function: for each hidden `<th data-col>`, it hides the same cell index in
every row of that table.

**Bug found and fixed before shipping**: the first implementation scoped
that lookup with a `:scope > tr` CSS selector, direct-child-of-table. It
matched nothing on any table, silently — the browser inserts an *implicit*
`<tbody>` around bare `<tr>` elements during HTML parsing even though this
file's source never writes one, so there is no `<tr>` that is a direct
child of `<table>` in the live DOM. Fixed with `table.rows`/`row.cells`,
the DOM API that already accounts for an implicit tbody and — unlike a hand
written selector — is scoped correctly against a *nested* table by spec:
`additions-roll-forward`'s monthly drill-down table sits inside a `<td>` of
the outer table, and `table.rows` on the outer table returns only the
outer table's own rows, never the nested table's.

`.cells` also does the right thing with a colspan'd row for free: an
empty-state row like `<td colspan="5">No rows entered</td>` has exactly one
entry in `.cells`, so indexing past it is simply out of bounds and guarded
— nothing is hidden on an empty-state row.

**A second bug found and fixed before shipping, more serious**: the restore
panel's "flag stale data" check (below) initially re-rendered a hidden
column's *owning tab* unconditionally to read its live cell content,
including when that tab was the one currently on screen. `MGM.bindAll()`
binds every `[data-k]` input directly, not via event delegation from a
stable ancestor, and runs *before* decoration in the refresh order
(`fn → bindAll → decorate → renderRestorePanel`). Re-rendering the active
tab's panel *after* bindAll already ran would silently unbind every input
on it for as long as the restore panel stayed open — found by tracing the
refresh order, not by a symptom. Fixed: the active tab is never
re-rendered for this check. It does not need to be — `display:none` hides
a cell, it does not clear `textContent`, so the data is already readable
from the tab's existing, already-bound DOM. Only *other* tabs (genuinely
off-screen, nothing bound to lose) get re-rendered to read their data.

## The "stale hidden column" safeguard

Permanent hide, as specified: a column hidden while every row reads "—"
stays hidden even once real figures populate it elsewhere in the model.
The one safeguard is informational, never automatic:
`MGM.staleHiddenColumns(ids)` checks whether a hidden column's table
currently holds any non-dash, non-empty value, and the restore panel shows
an inline nudge next to that item. Verified in the browser both ways: no
nudge when a column is genuinely still unset (`cost.unset === true`, every
cell reads "—"), and the nudge appears once real data is entered elsewhere
and the model recomputes.

## Restore panel: grouped by tab, then by type

At 211 possible ids a flat per-tab list is unreadable. `MGM.hiddenSectionType(id)`
classifies every id from its own shape (`-col-` → column, `-tile-` →
tile, trailing `-intro` → note, else → card) — a derived property of the id
text itself, never a second stored field, so there is nothing here that
could desync from `hiddenSections` the way two designs failed earlier in
this build. Each tab's group now shows up to four sub-groups: Cards, Stat
tiles, Intro text, Table columns.

## Testing

No engine (`membershipModel.js`) changes — `MM.sanitizeHiddenSections` is
already generic over any allowlist, so it needs no new tests; the existing
126/126 suite is unaffected and re-verified at the committed HEAD (SR-12).

Manually verified in a browser, this project's only test surface for page
JS: the 211-id bijection; tile/note hide via the existing `⊘` mechanism
with no changes needed; column hide/restore end to end including the
header **and** a same-column data cell going `display:none` together while
the adjacent column stays untouched; the nested monthly drill-down table
getting its own working hide buttons; the two control columns confirmed to
carry no `data-col`; the fully-excluded scenario-compare table confirmed to
carry zero `data-col` attributes; `restoreAllSections` clearing every type
at once; the restore panel's tab+type grouping and stale-column nudge, both
directions; and, after fixing the bindAll bug, a live input edit on the
active tab succeeding immediately after the restore panel (with its
staleness scan) rendered.
